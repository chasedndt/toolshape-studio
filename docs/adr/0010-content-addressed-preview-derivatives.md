# ADR 0010: Content-addressed preview derivatives and host resolution

**Date:** 2026-07-16
**Status:** Accepted for Milestone 5

## Context

Toolshape Studio needs thumbnails and waveforms for fast human editing and bounded agent inspection. The existing project model identifies these derivative kinds, but the media worker only creates a proxy. The web seed therefore draws simulated thumbnails and waveforms that are not evidence of the imported source.

Putting local file paths, browser blob URLs, data URLs, or renderer cache objects in `StudioProject` would make project state machine-dependent, leak private paths through adapters, destabilize hashes, and couple persistence to one UI host.

The existing derivative shape also requires a normalized audio/video probe even when the derivative is a PNG. Reusing the source probe would misrepresent what was actually generated.

## Decision

Thumbnail and waveform previews are immutable, content-addressed asset derivatives generated by a bounded media worker. Their canonical records contain `content://sha256/...` references, verified dimensions, source digest, toolchain, and timestamps. Image derivatives use `probe: null`; proxy derivatives retain their normalized media probe.

Advance the Studio project-document schema to version 3 and migrate older derivative records by preserving valid probes and normalizing a missing probe to `null`. The operation-envelope/capability contract remains at `0.1.0` because this change does not alter the public operation envelope.

Browser/native preview resolution is an adapter concern:

```text
canonical content ref
  -> trusted host preview resolver
  -> short-lived browser-safe URL
  -> Media / Audio / timeline view
```

The resolved URL is ephemeral. It is excluded from persistence, operations, semantic diffs, provenance, project digests, and render plans.

The initial worker emits one bounded thumbnail and one full-duration waveform PNG per audio-bearing video source. Videos without audio omit the waveform. Future tiled waveforms or cache levels may add derivative records without changing source truth.

## Consequences

### Positive

- Human previews correspond to real generated bytes instead of simulated CSS.
- Agents can inspect derivative identity, dimensions, lineage, and readiness without receiving unrestricted filesystem paths.
- UI, CLI, SDK, and future MCP/IPC adapters share one asset record.
- Native and web hosts may choose different secure URL mechanisms without migrating projects.
- Image derivatives are represented honestly instead of carrying a false media probe.

### Trade-offs

- The Studio project document requires a version-3 migration.
- A committed fixture resolver is needed for browser-only visual QA until authenticated native content resolution exists.
- One full-duration waveform PNG is sufficient for the alpha editor but not for deep timeline zoom or very long media.
- Content-addressed blobs written before a repository failure may require future orphan garbage collection.

## Alternatives rejected

- **Store filesystem paths in assets:** rejected for privacy, portability, and adapter safety.
- **Embed base64 previews in project JSON:** rejected because it bloats canonical state and destabilizes revisions.
- **Reuse the source probe for PNGs:** rejected because provenance must describe the derivative truthfully.
- **Continue drawing placeholder bars:** rejected because product-facing media evidence must correspond to actual source processing.
- **Generate previews in React:** rejected because UI adapters do not own media execution or domain truth.
